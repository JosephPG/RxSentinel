Caso 1:

1. El Grafo (Estructura en ArangoDB)Imagina estos nodos y relaciones mapeados con ArangoMappery:
Vértices: Usuario, Computadora, Servidor. Aristas: ACCEDE_A (con propiedad timestamp y metodo).

2. La ProblemáticaUn usuario ("Juan") se loguea en su PC. Minutos después, desde esa misma PC, se
intenta una conexión SSH a un servidor de archivos. Luego, ese servidor intenta conectar a la Base
de Datos de Producción. Individualmente, los logs parecen normales, pero la cadena es sospechosa.

3. Una consulta que busque si ese nuevo acceso conecta a un usuario estándar con un activo crítico
en más de 2 saltos:

    FOR v, e, p IN 1..3 OUTBOUND "Usuarios/juan" ACCEDE_A
    FILTER v.tipo == "ServidorCritico"
    RETURN {
        alerta: "Movimiento lateral detectado",
        ruta: p.vertices[*].nombre,
        pasos: LENGTH(p.edges)
    }


Caso 2:

Monitor de Ciberseguridad / Rastreador de Botnets:

El Flujo Reactivo: Recibes logs de intentos de inicio de sesión de diferentes IPs en tiempo real.

El Uso del ORM: Creas nodos para IP, Dispositivo y Ubicación.

La Lógica: Si una IP intenta entrar a 5 cuentas diferentes en menos de 10 segundos, el flujo reactivo lo detecta,
usa el ORM para vincular esa IP a una "Lista Negra" en ArangoDB y dispara una alerta de ataque de fuerza bruta.
